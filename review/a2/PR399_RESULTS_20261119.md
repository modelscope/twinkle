# PR information

## 背景

异步 GRPO 进程重启后，如果只恢复“已经生成了多少条轨迹”，仍会破坏训练语义：

- 一个 GRPO 组可能在旧 policy 和新 policy 下各补采一部分成员；
- ready 组可能在权重同步后使用错误 adapter 再次采样；
- batch 已经交出，但 optimizer checkpoint 是否持久化无法判断；
- 非幂等工具已经产生副作用，重启后又执行一次；
- 环境 session 丢失后，文本继续但 workspace 或工具状态已经不一致。

本 PR 将 `StreamingDriver` 的暂停/恢复升级为 Group-Atomic Durable GRPO。核心边界是
完整组、behavior policy、batch lease 和训练 checkpoint 必须一起提交或一起回退。

本 PR 不修改 GRPO loss、advantage 标准化和 sampler 生成算法。

## 主要改动

### 1. 显式 GroupPolicyBinding

新增与 Trainer、Sampler 解耦的策略绑定：

```python
GroupPolicyBinding(
    state_key="run/group/17",
    policy_version=4,
    adapter_path="/checkpoints/policy-4",
)
```

每个组在准入时固定这三项。恢复、no-slot retry、成员补采和组替换都必须沿用原
binding，禁止旧组用新 policy 补齐。

driver 快照同时写入结构化 `binding` 和旧版 `version/adapter_path` 字段：

- 旧快照可自动升级；
- 两份字段不一致时 fail closed；
- 空 `state_key`、负版本和空 adapter path 被拒绝。

### 2. 自动稳定边界持久化

启用 `resume_store` 后，`StreamingDriver` 自动在以下边界保存快照：

1. prompt 分配并完成成员提交；
2. 完整组进入 ready 队列；
3. batch lease 写入；
4. checkpoint commit 后清 lease；
5. 组淘汰。

调用方不再需要在故障前手工调用 `state_dict()`。恢复直接使用：

```python
driver.load_state_dict()
```

自动快照的写入顺序与 journal 事件配对：

- lease 先进入 driver 快照，再写 `BATCH_LEASED`；
- group ready 先进入 driver 快照，再写 `GROUP_READY`；
- `MODEL_CHECKPOINT_COMMITTED` 是 commit 的事务点，恢复时用它退休旧 lease。

### 3. Batch lease 与训练 checkpoint 关联

新增：

```python
driver.commit_batch(checkpoint_ref, manifest)
```

训练侧只有在 adapter、optimizer、scheduler 和 RNG state 完整持久化后才能调用。
未提交前崩溃：恢复上一 checkpoint，并重交付同一 batch lease；已提交后崩溃：
恢复新 checkpoint，不再交付同一 lease。

### 4. ResumableEnv 独立协议

Env 恢复能力作为独立 `ResumableEnv` protocol 提供，不向所有 `Env` 实现增加空方法：

```python
EnvResumeCapability.NONE
EnvResumeCapability.LIVE_ATTACH
EnvResumeCapability.DURABLE_CHECKPOINT
```

`LocalEnv` 显式实现 durable checkpoint。`AgentEnv`、`OpenEnv` 和 `OpenEnvClient`
默认无恢复能力；episode 已打开但环境不能恢复时拒绝静默继续。

### 5. 工具副作用与环境状态

- 工具调用使用 `TOOL_INTENT -> episode checkpoint -> TOOL_RESULT`；
- pending intent 没有可证明的结果时拒绝恢复；
- 已 checkpoint 的 effect 直接复用 observation，不再次执行外部副作用；
- `MultiTurnRollout` 保存 token、labels、mask、old logprob、tool loop 和 LocalEnv
  workspace；
- 无法 checkpoint 的 harness 和 message-ledger episode fail closed。

### 6. Journal 与对象存储

`DurableJournal` 使用 hash-chain JSONL，支持：

- 最后一行截断修复；
- 中间记录损坏拒绝；
- 跨线程和跨进程 writer 锁；
- append/fsync 失败回滚；
- object SHA-256 校验和原子 rename。

## 兼容性

- `resume_store=None`：保持原有内存 streaming 行为；
- 所有 durable 能力必须显式传入 store；
- 旧 `version + adapter_path` 快照继续可读；
- `twinkle_agentic.envs.base` 的旧导入路径保持兼容；
- 无 checkpoint manager 时仍可保存组和 lease，但不执行 policy 版本淘汰；
- 新 `ResumableEnv` 推荐从 `twinkle_agentic.envs.resume` 导入。

核心生产代码新增量保持在 2000 行以内。

## 1. 真实 Qwen + NPU checkpoint 强杀

本轮强杀探针不调用 `driver.state_dict()`，只依赖 driver 自动持久化。

| 强杀边界 | 返回码 | 恢复 checkpoint | 同 lease 重交付 | optimizer step |
|---|---:|---|---:|---:|
| optimizer step 后、adapter 保存前 | `-9` | `step-0` | 2 行 | `[]` |
| 临时 adapter/optimizer 保存后 | `-9` | `step-0` | 2 行 | `[]` |
| checkpoint 原子发布后、commit 前 | `-9` | `step-0` | 2 行 | `[]` |
| journal commit 后 | `-9` | `step-1` | 否 | `[1]` |

四个场景均通过 LoRA digest 和 optimizer state 校验。未提交 optimizer 更新不泄漏；
已提交 batch 不重复训练。

证据：

- `review/a2/NPU_CHECKPOINT_KILL_AUTOMATIC_RESULTS_20261119.md`
- `review/a2/npu-checkpoint-kill-auto-evidence-20261119-final/report.json`

## 2. 聚焦回归

- 本地：`45 passed`
- A2 Python 3.10：`45 passed`

覆盖范围：

1. 不手工 `state_dict()` 时恢复 prompt、ready group、lease 和 commit；
2. 旧扁平快照升级为 GroupPolicyBinding；
3. binding 冲突、空 ID、负版本和空 adapter path 拒绝；
4. 无故障 baseline/durable 等价；
5. journal 截断、损坏、SHA 错误、ENOSPC、rename 中断和并发 writer；
6. 真实 optimizer checkpoint 事务；
7. Env 无恢复能力时 fail closed；
8. 非幂等工具不重复执行；
9. adapter 缺失、路径复用和 staleness 整组淘汰。

## 3. 无故障等价与开销

确定性无故障控制：

- baseline 与 durable 均为 8 次 optimizer update、0 丢失组；
- 训练信号逐值一致；
- 16 条评测样本逐值一致；
- `accuracy_delta=0`、`reward_delta=0`。

A2 本地文件系统开销：

| 指标 | 结果 |
|---|---:|
| journal append | `10.36 ms/event` |
| journal 吞吐 | `96.55 events/s` |
| journal 存储 | `530.56 B/event` |
| object save | `0.55 ms/object` |
| 存储放大 | `1.0326x` |

## 4. GSM8K 故障恢复训练 A/B

对照为“故障点丢弃整个 ready group”与“durable 保留同一 policy 的完整组”。

25% 故障率下最终质量收益不稳定，因此不作为主要结论。

50% 故障率、64 个训练组、512 条未参与调参的官方测试：

| 指标 | baseline | durable | 差值 |
|---|---:|---:|---:|
| 准确率 | `167/512` | `191/512` | `+4.6875pp` |
| reward | `0.42617` | `0.49297` | `+0.06680` |
| 有效 optimizer step | `32` | `64` | `+32` |
| 丢失完整组 | `32` | `0` | `-32` |

精确 McNemar 双侧 `p=0.0018416`；paired bootstrap 95% 区间
`[+1.953125pp, +7.6171875pp]`。

扩展到 128 个训练组、50% 故障，并在全新的官方 `test[768:1024]` 上评测 256 条：

| 指标 | baseline | durable | 差值 |
|---|---:|---:|---:|
| 准确率 | `92/256` | `116/256` | `+9.375pp` |
| reward | `0.47578` | `0.61094` | `+0.13516` |
| 有效 optimizer step | `64` | `128` | `+64` |
| 丢失完整组 | `64` | `0` | `-64` |

精确 McNemar 双侧 `p=0.0007173`；paired bootstrap 95% 区间
`[+4.296875pp, +14.453125pp]`。

两个独立确认种子在未参与调参的测试切分上分别取得 `+2.34375pp`，方向一致。

## 结论边界

已经证明：

- 真实 Qwen/NPU 强杀后，模型 checkpoint、optimizer、lease 和 journal 保持一致；
- 自动快照不依赖人工 `state_dict()`；
- 未提交 optimizer step 不泄漏，已提交 batch 不重复训练；
- 无故障路径质量等价；
- 50% 组丢失故障下，固定预算训练收益显著提高。

尚未证明：

- 可写 NFS 或对象存储上的 lease、journal 和 adapter 故障矩阵；
- 多卡 HCCL/FSDP2 和更大模型；
- 所有远端正环境都具备 checkpoint 能力；
- 所有外部工具协议都能查询幂等结果。

因此本 PR 结论限定为“完整组丢失或进程重启时保持 GRPO 语义、事务一致性和固定预算
有效训练量”，不宣称所有故障率或生产存储下无条件提升。
