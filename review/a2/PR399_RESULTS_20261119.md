## 目标

把 streaming rollout 的断点恢复升级为 Group-Atomic Durable GRPO：

- 恢复后保留完整 GRPO 组；
- group 从准入到训练固定 behavior policy 和 adapter；
- 禁止旧组用新 policy 补采成员；
- batch lease 与训练 checkpoint 建立可验证关联；
- 工具副作用无法证明幂等时 fail closed。

## 核心改动

- 新增 hash-chain JSONL journal、对象 SHA-256 校验和原子写入。
- `DurableJournal` 增加线程锁、跨进程文件锁和写入失败回滚，避免并发 writer
  分叉 hash chain。
- `StreamingDriver` 保存 prompt、未完成组、ready 组、DataLoader state 与 batch lease。
- group 固定 `policy_version + adapter_path`；恢复、no-slot retry 和成员补采沿用同一绑定。
- ready group 超 staleness 时整组淘汰，禁止混入新策略。
- `commit_batch(checkpoint_ref, manifest)` 记录训练 checkpoint、batch 和 policy versions；
  空 checkpoint reference 被拒绝。
- `ClientCheckpointManager` 保留历史 adapter path；episode 每次采样显式使用绑定路径。
- `MultiTurnRollout` 保存/恢复 token 真值、tool loop 状态和 LocalEnv workspace。
- 工具 effect 使用 intent/result 边界；无法确认结果时拒绝不安全恢复。

核心生产代码新增约 1100 行，低于 2000 行预算。

## 验证结果

### 1. 聚焦回归

- 本地：`33 passed`
- A2 Python 3.10：`33 passed`

新增边界覆盖：

1. 无故障等价与 journal/object 开销；
2. 真实 torch optimizer checkpoint 事务；
3. Linux `SIGKILL` 五阶段恢复；
4. exactly-once lease/commit；
5. journal 截断、损坏、SHA 错误、ENOSPC、rename 中断和并发 writer；
6. Env 无恢复能力时 fail closed；
7. 非幂等工具不重复执行；
8. adapter 缺失、路径复用和 staleness 淘汰。

### 2. 真实 Qwen + NPU checkpoint 强杀

A2 Ascend 910B4、Qwen3-0.6B、LoRA rank 8、BF16、官方 GSM8K：

| 强杀边界 | 进程返回码 | 恢复结果 |
|---|---:|---|
| optimizer step 后、adapter 保存前 | `-9` | 恢复 `step-0`，同一 lease 重交付 2 行 |
| 临时 adapter/optimizer 保存后 | `-9` | 临时 checkpoint 不生效，恢复 `step-0` |
| checkpoint 原子发布后、journal commit 前 | `-9` | 已发布 checkpoint 不生效，恢复 `step-0` |
| journal commit 后 | `-9` | 恢复 `step-1`，optimizer step `[1]`，不再交付 |

四个场景的 LoRA 权重 digest 和 optimizer state 均通过恢复校验。未提交更新不会泄漏，
已提交 batch 不会重复训练。

### 3. A2 Qwen 真实采样进程恢复

- 24 个已采样 token 逐值保留；
- token/labels/mask/old logprob 不重新编码；
- 恢复后继续采样 16 token，logprob 有限；
- LocalEnv 恢复后读到 `turn-1-durable`。

### 4. 无故障等价与开销

确定性无故障控制：

- baseline 与 durable 均为 8 次 optimizer update、0 丢失组；
- 训练信号逐值一致；
- 16 条评测样本逐值一致；
- `accuracy_delta=0`、`reward_delta=0`。

A2 本地文件系统开销：

| 指标 | 结果 |
|---|---:|
| journal append | `10.36 ms/event` |
| journal 吞吐 | `96.55 events/s` |
| journal 存储 | `530.56 B/event` |
| object save | `0.55 ms/object` |
| 存储放大 | `1.0326x` |

4 个独立进程并发写 200 条 journal，sequence 连续且 hash chain 有效。

### 5. GSM8K 故障恢复训练 A/B

对照为“故障点丢弃整个 ready group”与“durable 保留同一 policy 的完整组”。
使用官方 GSM8K、Qwen3-0.6B、LoRA、单卡 910B4。

25% 故障率下最终质量收益不稳定，因此不作为主要结论。

50% 故障率、64 个训练组、512 条未参与调参的官方测试：

| 指标 | baseline | durable | 差值 |
|---|---:|---:|---:|
| 准确率 | `167/512` | `191/512` | `+4.6875pp` |
| reward | `0.42617` | `0.49297` | `+0.06680` |
| 有效 optimizer step | `32` | `64` | `+32` |
| 丢失完整组 | `32` | `0` | `-32` |

精确 McNemar 双侧 `p=0.0018416`；paired bootstrap 95% 区间
`[+1.953125pp, +7.6171875pp]`。

扩展到 128 个训练组、50% 故障，并在全新的官方 `test[768:1024]` 上评测 256 条：

| 指标 | baseline | durable | 差值 |
|---|---:|---:|---:|
| 准确率 | `92/256` | `116/256` | `+9.375pp` |
| reward | `0.47578` | `0.61094` | `+0.13516` |
| 有效 optimizer step | `64` | `128` | `+64` |
| 丢失完整组 | `64` | `0` | `-64` |

精确 McNemar 双侧 `p=0.0007173`；paired bootstrap 95% 区间
`[+4.296875pp, +14.453125pp]`。

两个独立确认种子在未参与调参的测试切分上分别取得 `+2.34375pp`，方向一致。

## 结论边界

已经证明：

- 真实 Qwen/NPU 训练进程强杀后，模型 checkpoint、optimizer、lease 和 journal
  保持提交/回退一致；
- 不提交的 optimizer step 不会泄漏，已提交 batch 不会重复训练；
- 无故障路径质量等价；
- 50% 组丢失故障下，durable 机制显著提高固定预算下的有效训练组和 GSM8K 指标。

尚未证明：

- GSM8K A/B 使用独立训练脚本模拟“组被丢弃/被保留”，尚未把完整故障注入接到
  真实 Twinkle training cookbook 的 `StreamingDriver + commit_batch`；
- 尚未完成可写 NFS/对象存储下的 lease/journal/adapter 故障矩阵；
- 尚未完成多卡 HCCL/FSDP2 和更大模型验证；
- agent-program harness 及无法 checkpoint 的远端正环境继续 fail closed。

因此本 PR 当前结论限定为“故障条件下保留完整 GRPO 组、维持事务一致性并改善
固定预算训练收益”，不宣称所有故障率或生产存储下均无条件提升。
